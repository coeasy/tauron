## 0. 阅读方式与三条硬约束

三份方案在结论上高度一致，分歧只在命名体系（R / DX-INT-IND / Phase A-H）。本计划把它们**映射到同一套任务编号**，并给出交叉索引：

- **T-x** = 本计划的任务号（唯一真源）。
- 每个任务标注它覆盖的旧方案编号，便于对照。

三条不可违背的纪律（全部继承，尤其第 2 条是新增的对偶约束）：

1. **诚实纪律只增不减**：任何改进不得用伪造成功换绿灯；`simulated` / fail-closed 语义保留并扩展到全仓。
2. **占位必须有归宿**：每个 ⚪/🧩 半成品要么排进"转正"批次，要么排进"删除/降级 private/移出发布面"批次——**不允许无限期挂着半成品**。
3. **文档数字一律来自构建产出**：手写数字即 bug；单一真源是 `contracts/facts.json`。

**落地可行性分级**（避免把无法在本环境完成的事当成"已实现"）：

- `CODE`：纯仓内代码/脚本改动，可在本地 `cargo`/`node` 验证。
- `CI`：需要在 GitHub Actions 三平台 runner 上跑的矩阵/证据（本地只能写 workflow，无法证明绿）。
- `OPS`：仓库/账号侧操作（分支保护、发 npm/crates.io、外部审计），非代码可交付。
