## 1. 项目主要功能梳理

### 1.1 定位

tauron 是**建在 Tauri 2 之上的"插件化桌面客户端基础设施"**：不是成品应用，而是让一个桌面客户端能安全加载第三方代码、互相隔离、授以受控能力、并能不发版替换它们的底座。它自称分两层、可分开取用：

- **框架层**：信封协议 `plugin_invoke`（单命令统一 调用/取消/进度）、`PluginType` 四形态、双层 ACL、事件总线、配置四层合并、插件市场（Ed25519）、CLI。
- **应用层**：`host_*` 命令族（85 条）、生命周期状态机、三档授权、设置中心、白标/主题、i18n/通知、崩溃恢复、更新通道、UI 组件、Event 审批与生产就绪自检。

**结论（回答"核心功能是否全部实现"）：** 底座治理面（命令层/生命周期/授权/设置/恢复/白标/主题/i18n/通知/审计）是**真的且已贯通**；但**"插件系统"这个题眼本身没有一条完整可跑的链**——框架层无生产分发器（❌），四种插件形态里只有 Process 是真链（且 Production fail-closed）、JS 半通且投递不诚实、WASM 引擎造好了但投递断、Rust 根本没路；网络闭环（下载/商城/升级）全是 trait 接缝 + 诚实 `simulated`。

### 1.3 "主体链路是否全部贯通"的分链判定

| 链路 | 贯通性 | 断点 |
| --- | --- | --- |

| B 应用层 host_* 85 命令 | ✅ 通 | origin_gate 唯一咽喉 100% 覆盖；示例 app 真装配、dist 已构建 |

## 3. 根因诊断（为什么会长成这样）

在展开重构前，先说清楚结构性成因，否则重构会重蹈覆辙：

1. **"诚实占位 + 门禁"文化把激励放在了"绝不伪造成功"上，但没同步投入"把真实路径补完"。** 门禁（尤其 `simulated-never-commits`/`success-requires-effect`）能死死钉住已知的假成功模式不许复现，于是团队倾向"先把接口造出来、标 simulated、留个 honest 失败码"——安全、CI 绿、还显得成熟。结果是一堆**造了一半的引擎**（wasmi 全引擎零入口、FFI 全套、多语言 fixture 不编译、core 上一代编排 API 不删）。诚实纪律本身是对的，缺的是配套的"占位必须有转正 DDL 或明确废弃"的约束。

2. **round-by-round 的微修文化（已到 round 69）累积了大量并行态。** 每一轮针对一个具体 bug/一致性收紧，但极少做"合并重复"的横向重构。于是出现：两套身份解析、两套 readiness、三套命令名清单、两套签名机制都叫 signature、双份事件总线/注册表——全靠"锁步测试"和注释维持不漂移，认知负担极高。

3. **feature-flag 组合爆炸侵蚀了贯通性。** `tauri` × `plugin-install`(122 处 cfg) × `runtime-wasm-broker` × 4 档部署形态，把"默认装配能不能跑通一次真调用"这件事推给了接入方。WASM/Rust 投递断链，很大程度上是"接进默认装配要跨 feature 矩阵"的成本被推迟了。

4. **文档增长快于数字同步。** 六份方案文档、257KB CHANGELOG、README 特性表各自维护"测试数/命令数/版本号"，没有一个由构建产出注入的单一真源；`docs:check` 又恰好不覆盖方案文档，于是数字腐烂无人管。

## 4. 不合理之处（功能 / 架构 / 实现 / 文档四维）

按严重度 P0（影响核心可用性/正确性）、P1（结构欠债/一致性）、P2（卫生/体验）分级。

### 4.1 功能维度

- **P0-F1 题眼不闭合**：作为"插件系统"，没有一条端到端可跑的插件执行链处于默认可用状态（框架层 ❌、Rust ❌、WASM ❌、JS 🟡 投递不诚实、Process 在 Production ⚪ fail-closed）。这是最大名不副实点。
- **P0-F2 "两层可分开取用"误导**：框架层无生产装配，示例里 shell handler 只是注释。要么给框架层一个真生产分发器，要么承认它是"协议 + 类型面"而非"可独立使用的框架层"。
- **P1-F3 孤儿发布面**：`dual-world`、`shell-matrix` 零消费者却发公有 npm；`@tauron/core` 六+死导出；`market/api.rs` 的 `MarketplaceApi` 零消费者（伪装成商城能力）。公开 API 面被未接线原型充数。
- **P1-F4 网络闭环全 trait**：下载/商城安装/升级缺省生产走 `NoUpgradeInstaller`，真腿 `DistributeUpgradeInstaller` 仅 `#[cfg(test)]` 构造。Ed25519 只保护本地 `.tpkg`，`check_for_update` 签名校验是 `is_empty()` 占位。
- **P2-F5 适配层 reference-only**：react/vue/svelte 三适配器无活消费者，示例只演示 vanilla。

### 4.2 架构维度

- **P0-A1 lib.rs 21,281 行单文件 / 412 顶层项 / 零模块树**：全仓最大结构异味。分组只靠 34 条注释横幅；8 个测试模块内联在巨型文件里。约 5× 于其它任何文件。
- **P1-A2 薄领域 / 厚编排反模式**：10 个几百~1.5k 行薄 crate + adapter(27k)/host(22k) 巨厚。`.tpkg` 安装事务（下载→验签→解压→原子交换→回滚）在 adapter 里重写了一套，而 distribute 已有 `run_phases` 骨架——应下沉。
- **P1-A3 并行态泛滥**：两套身份解析、两套 readiness（死 `readiness.rs` vs 活 `production.rs`）、三套命令名清单、两套"签名"(Ed25519 vs HMAC 同名)、theme 双真相源（crate 自持久化 + adapter `Arc<Mutex<ThemeRegistry>>`）、settings 落盘逻辑分散三处。
- **P1-A4 origin_gate 语义被夸大**：README/plan 说"origin_gate 在副作用前做身份判定"。实读 `tauri.rs:3010` 明写"不解身份、不查 ACL、不加 origin 门，身份判定属于业务体"；它只判 webview origin，且 SubstrateState 未 manage / Dev 空 allowlist 时**是 no-op**。真正身份判定分散在 ~42 个命令体内 `require_main_window`（`lib.rs:4676`），只由测试兜底。把 origin_gate 当"身份咽喉"会诱导新命令漏 `require_main_window`。
- **P1-A5 审计覆盖 < 强制覆盖**：`ADMIN_COMMANDS` 审计表 8 条，而 ~42 条命令调 `require_main_window`——特权面比被审计记录的面大得多。

### 4.3 实现维度（缺陷）

- **P0-I1 JS 投递 fail-open**：`eventbus.rs:1076` 仅队列收下即 `delivered:true`，不校验有活消费者；关窗的 JS 插件调用会谎报"已投递"然后干等 pending TTL。这与 Process 侧 `live_runtime` 检查（`process_delivery.rs:141`）的诚实标准不一致——**诚实纪律在 JS 链上有个洞**。
- **P1-I2 配置四层合并非确定 + 无作用域**：`shell/config.rs:79-83` `get(key)` 不接 plugin_id，遍历 `HashMap<plugin,overrides>` 全量取覆盖——两个插件覆盖同键时谁赢取决于哈希序（非确定），且某插件覆盖对所有消费者全局生效。且该模块整体未接线（零生产消费者）。
- **P1-I3 adapter 层并发原语违背 §4.1**：lib.rs **24 个 `Arc<Mutex<..>>`、零 RwLock、零 ArcSwap**；把内部已 `RwLock` 同步的 `EventBus` 再套一层 `Arc<Mutex>`（`lib.rs:3294`），7+ 处 `.lock()`——读多写少总线被排他锁串行化，双重加锁。
- **P1-I4 clipboard 写副作用谎报 unsupported**：`cmd_clipboard_write` 先改进程内 buffer，再返回 `Unsupported`——"声明不支持却已产生状态变更"（读侧诚实）。
- **P1-I5 约 50 个 `cmd_*` 无 guard/boundary 包裹**：panic 捕获（`run_*_boundary` + `catch_unwind`）只覆盖 ~86/137；未包裹者一旦 panic 会挂住 JS `invoke()`（正是 Tauri issue #10327 的失败模式，`tauri.rs:2954` 自己警告过）。
- **P2-I6 非测试路径 unwrap panic 点**：`theme/lib.rs:251`（空注册表）、`brand/lib.rs:248/254`、`i18n/lib.rs:52`（locale 空段）。
- **P2-I7 FFI 多语言 fixture 名不副实**：C 真跑 ASan；C#/Swift/Kotlin 只在 `lib.rs:454` 做子串存在性检查，从不编译执行。
- **P2-I8 WASM 无 per-call host_fn 截止**：`call_timeout_ms` 仅配置校验，运行时只靠 fuel；guest 若阻塞在 host_fn 内无引擎侧 deadline。

### 4.4 文档 / 元维度（本次独立审计最集中的"不合理"）

- **P1-M1 测试数字全面腐烂且互相矛盾**：实测 Rust 声明 1715 / TS 文件 107；README 徽章 1426、README 正文"声明 1498"、V10"1284+"、竞品"1221"——没有一个对，且这些数字被当产品可信度卖点。`docs:check` 不覆盖方案文档，腐烂静默。
- **P1-M2 六份重叠方案文档 + V10 引用最旧基线**：V4(194KB)/V5/V7/V8/V9/V10 + 488KB v4-gap-closure + 257KB CHANGELOG。最新的 V10 反而带最旧测试数——"新文档=更可信"在此不成立。仓内 `docs/architecture/README.md` 已在 round 50 删过 4 份同类文档，却没删剩下的。
- **P1-M3 版本三分叉**：repo/package `1.1.0`、registry `1.0.2`、tag `v1.1.0` 落后 main 26 commit（指向 round13-18 树）。`version:check` 只校内部一致、不比 tag/registry，故"绿着却分叉"。对消费者是最大实际坑。
- **P1-M4 门禁"有牙齿但作用域窄"**：`simulated-never-commits` 只扫 6 文件、`success-requires-effect` 11 文件、`upgrade-file-hash` 只钉 1 文件；全是自认"deliberately NOT parsers"的文本针扫——改名/走宏/间接置 `simulated` 可绕。它保证的是"已记录的假成功模式不在原地复现"，**不是**"任何地方都不存在伪造成功"。多数针门无 `--self-test`（仅 2 个有）。
- **P2-M5 "9 ledger"口径错误**：contracts 实为 **8** 个 json；README 的"9"指应用层 9 包。无 `contracts/README.md` 枚举。
- **P2-M6 分支保护未开（N-23）**：CI 唯一没被强制的一环，文档已承认但仍开放。
- **P2-M7 命令面定义分散三处**：`grep 'pub fn host_'` 原始 81，生成物/门禁用 85——命令名清单/handler 宏/authz tier 表三处靠锁步测试对齐，是 §4.2-A3 的一个实例。

## 5. 重构方案（分阶段，只出方案）

### 5.0 设计原则（不可违背）

1. **诚实纪律只增不减**：任何阶段都不得用伪造成功换绿灯；`simulated`/fail-closed 语义保留并扩展到全仓。
2. **占位必须有归宿**：每个 ⚪/🧩 要么排进"转正"批次，要么排进"删除/降级为内部/移出发布面"批次——不允许无限期挂着半成品。
3. **先纯搬运、后改语义**：大重构（拆 lib.rs）第一步只做文件移动 + `pub use`，用两 feature profile 的 `cargo check` 证明零行为变更，再动逻辑。
4. **单一真源优先**：并行态（数字/命令面/身份/注册表/签名）一律收敛到"一个源，其余生成/引用"。

### R0 · 止血与速赢（低风险，1 周内可完成；不动运行链）

目标：修掉所有"说谎的数字"和零成本结构坑，先让仓库对外口径可信。

- **M1/counts**：新建一个由构建产出的"事实文件"（`contracts/facts.json`，在 CI 里由 `cargo test` 汇总 + grep 生成），README 徽章、V1x 基线、竞品文档的测试数/命令数/版本一律**读取该文件**，删除所有手写数字。即刻修正为：Rust 声明 1715、TS 文件 107/20 包、命令 85(61/22/2)。
- **M3/version**：解决 tag 分叉——要么把 `v1.1.0` 重切到当前 HEAD，要么删 tag 改切 `v1.1.0-rc`；并给 `version:check` 增加"tag==HEAD 树 / registry 目标版本"比对维度（当前只比内部）。发布与否单独决策，别再"1.1.0 未发 + tag 指向旧树"双坑。
- **A4/origin_gate 口径**：把 README/plan 里"origin_gate 做身份判定"改为真实的分层描述（origin 白名单在唯一分发点；身份=各命令体 `Caller`+`require_main_window`）；文档错一处比代码少一处更危险。
- **孤儿清理（零消费者且无人接管的）**：删 `market/api.rs` 的 `MarketplaceApi`（保留 lib.rs 真逻辑）；删死的 `host/readiness.rs`（保留活的 `production.rs`）；`@tauron/core` 六个死导出——按门禁自身建议"接消费者 / 去 export 降级 / 登记台账"三选一处理；`dual-world`/`shell-matrix` 移出公共发布面或标 `experimental`+`private`（见 R2）。
- **门禁硬化（低成本）**：把 `--self-test` 接到**所有**针门（现在只有 2 个有），给 `upgrade-file-hash`/`wasm-loaded-generation` 加变异夹具防"改名即静默绿"；`docs:check` 白名单纳入 6 份方案 + 竞品文档，或显式标注为"历史冻结、行号不保证"。
- **P2-I6**：收掉 theme/brand/i18n 三处非测试 unwrap，改显式错误返回。
- **治理**：开 `main` 分支保护 + 挂全部 CI job 为必需状态（N-23）。

退出判据：CI 全绿且不再有任何手写数字；`version:check` 能抓 tag/registry 分叉；孤儿 API 从发布台账消失或登记去向；`main` 受保护。

### R1 · 核心链路贯通（本方案旗舰；中高风险，按插件形态分四批）

目标：把"插件系统"从 wire-only 变成**至少一条形态端到端默认可用**，并消除诚实洞。**全程保持 fail-closed，转正后由同风格的 E2E 门锁定。**

统一前提：把 `PluginType` 的四形态投递收敛为**单一 `RuntimeDriver` trait**（Js/Process/Wasm/Rust 共用一套 dispatch/liveness/settle 面），先消除 JS 用队列、Process 用 map、Wasm/Rust 用 Unwired 的不对称。

- **R1.1 JS 投递去 fail-open（先补诚实洞，成本最低）**：`delivered:true` 必须以"目标插件的入站泵已注册/窗已 bootstrap"为前置，否则 `delivered:false`→`E_PLUGIN_TYPE_NO_RUNTIME`，对齐 `process_delivery.rs:141`。加一条 E2E：关窗后调用不得报 delivered。
- **R1.2 WASM 投递转正（最高价值、两把锁）**：(a) 落地线性内存 string/JSON ABI（guest 导出 allocator + memory，长度前缀 UTF-8 双向传参），替换 `(i64,i64)->i64`；未实现的签名继续 `UnsupportedSignature` fail-closed。(b) 落地 ADR-10 supervisor——**复用已验证的 `tauron-proc` 帧机构**（`CommandSpawner`+JSON-RPC 行协议+代际守卫）把 wasmi 跑在子进程，并在此处补上 per-call host_fn 截止(I8)。(c) 只有 (a)+(b) 就位后，`WasmCallDelivery::deliver` 才改真执行，`delivered:true` 必须与一条 `sidecar_e2e` 风格的真 E2E 同轮落地，并保留 `wasm-delivery-supervisor` 门禁（`delivered:true` 永不早于 supervisor 存在）。
- **R1.3 Rust 执行器二选一**：要么注册编译期内置插件为 `RuntimeDriver` trait 对象、进程内带 ACL 分派；要么把 Rust 插件编译成原生 sidecar **直接复用 Process 链**（继承其容器/崩溃预算/帧回路/Production fail-closed 姿态）。在选定并落地前，保持 `E_PLUGIN_TYPE_NO_RUNTIME` 不动。推荐后者——增量最小、复用真链。
- **R1.4 Process 在 Production 可用**：现状 Production 要求 Hard 沙箱而实现只给 Partial（仅进程树隔离），导致生产默认拒绝 spawn。要么补 OS 级 fs/net/syscall 隔离（Linux seccomp/landlock、Windows restricted token + Job）达到 Hard，要么把"Production=Partial 可用（明确降级隔离等级，诚实标注边界）"作为一档受支持形态显式化。二者都比"默认拒绝"更接近"能用"。
- **R1.5 框架层 plugin_invoke 定性**：正面回答 P0-F2——**推荐"收敛"**而非"补全"：把 `tauron-shell` 定位为"协议/类型/serde 门面的单一真源"，其 `plugin_invoke` 的生产分发**委托**到 canonical `tauron-adapter/host`（一个真 `PluginDispatcher` impl 桥），并删除与 host 并行的 legacy registry/eventbus/config；`ConfigLayer`/内层 ACL 要么接进 `handle_invoke` 要么移出特性表宣称。这样"框架层可独立取用"才成立。

退出判据（每形态一条硬 E2E）：存在 ≥1 种插件形态在**默认（Production）装配**下从 `invoke` 到 `settle` 真跑通并有仓内测试；JS 不再有 fail-open；WASM 有真 supervisor 子进程链或明确停在诚实占位；Rust 有明确选定路径。

### R2 · 结构重构（最大杠杆；中风险，纯搬运优先）

- **R2.1 拆 21k lib.rs**：沿 34 条注释横幅切成 `src/{state,caller,registry,lifecycle,events,stream,settings_txn,http_policy,scoping,install,market_updater,notify,dialogs,contributes,brand}.rs`，`caller.rs` 统一 `Caller/admin_gate/require_main_window`。**第一步纯 move + `pub use`**，两 feature profile `cargo check` 证明零语义变化；platform-independent 属性（lib 不 import tauri）保持不变。`plugin-install` 的 122 处 cfg 集中到 `install.rs` 一处门。
- **R2.2 单一命令面真源**：以 handler 宏为权威，生成 `SUBSTRATE/PLUGIN_RUNTIME/PLUGIN_INSTALL_COMMANDS` 常量 + authz tier 表 + 审计表，消灭三套清单；把 `ADMIN_COMMANDS` 扩到 == 全部 `require_main_window` 命令，使**审计覆盖 ≥ 强制覆盖**（修 A5）。
- **R2.3 消灭并行态**：身份解析归一（`resolve_self_identity` 与 `resolve_principal` 合成一个）；`service_graph` 要么真驱动启动顺序要么删并降级为装配断言；`provider.rs`(A74) 删除并入未接线台账；主题双真相源二选一（推荐 theme 走内存态 + adapter 统一落盘，对齐 settings）；抽一个共享 `atomic_write(path,bytes)` 原语供 settings/theme/acl 复用；两套"签名"在命名上区分（`package-signature(Ed25519)` vs `grant-mac(HMAC)`），文档别再暗示"处处 Ed25519"。
- **R2.4 薄领域/厚编排再平衡**：把 `.tpkg` 的"验签→解压→原子交换→回滚"骨架从 adapter 下沉进 `tauron-distribute`（它已有 `run_phases`），adapter 只做 trait 注入。合并呈现类小 crate（theme+brand+i18n→一个 `tauron-presentation`），按"有磁盘状态 vs 纯逻辑"重划领域 crate 边界，收窄 workspace 依赖面（schema 现在还得经 settings 间接消费）。
- **R2.5 包合并**：三适配器收成一个 `@tauron/adapter`（子路径导出 react/vue/svelte），`dual-world`/`shell-matrix` 转 private/experimental，core 死面退役——把 21 包压到约 15，公开面台账不再被原型充数。

退出判据：lib.rs 无单文件 >3k 行；命令/身份/注册表/签名各仅一处定义；`cargo check` 默认+tauri+plugin-install 三档皆过且行为不变；发布面孤儿数（gate A-ratchet）显著下降并重新留出余量。

### R3 · 网络闭环贯通（下载/验签/商城/升级成真；中风险）

- 补一个仓内 `HttpDownloader`（workspace 已含 rustls）+ 生产 `Ed25519SignatureVerifier`（复用 `market::verify_tpkg_reader`）**填上 distribute 现在只有 `#[cfg(test)]` 的两处 trait 接缝**。
- 给 `DistributeUpgradeInstaller` 一条**缺省可装配**入口（feature 内 builder），替代 `NoUpgradeInstaller` 默认；`check_for_update` 的 `is_empty()` 占位接到真 verifier。
- `market` 的 search/install 若不做真后端，就把 `api.rs` 从发布面移除（R0 已删 mock），避免"桩冒充商城"；`host_market_*` 明确标桩或实现。
- journal 启动自恢复（round 67 已接线但默认休眠：`upgrade_recovery_paths` 缺省 None）改为缺省宿主即启用扫描对账。

退出判据：存在一条"下载→Ed25519 验签→解压→原子交换→崩溃回滚"的真闭环测试（非 Mock），Production 档默认装配即可触发（或明确 feature 开关且有文档）。

### R4 · 安全 / 持久化 / 投递收口（中风险）

- 身份/特权强制从"每命令体约定 + 锁步测试"升级为**handler 接线属性**（如 `admin_gate` 包裹的注册形态），新命令漏判在编译/门禁层被拦，而非靠人记得调 `require_main_window`。
- `network_policy` 默认 sink 从 `UnavailableHttpSink` 提供一条可开箱启用的真 HTTP sink（含 DNS rebinding 复检闭环），否则三层判定只在注入时有效。
- 补齐 V9 遗留安全项：`SecretProvider`（现零命中）、token 请求侧重检、遥测 redaction。
- `time_trust.suspicious_if_skew_exceeds`（零消费者）接进实际校验或删除。
- WASM 补 per-call host_fn 截止（I8）。

### R5 · 文档与治理收口（低风险，持续）

- 把 V4–V10 六份方案 + 488KB v4-gap-closure 收敛为**一份"当前状态 + 开放项"活文档** + `docs/archive/` 冻结历史（明确标"行号/数字不保证"）。
- CHANGELOG 257KB 拆分（保留最近 N 轮 inline，其余归档）。
- 新建 `contracts/README.md` 枚举 8 ledger 及其消费者与读取它的门禁。
- 把针门作用域从"5–6 个硬编码文件"扩展为**全仓** `success 必带 effect/simulated` 扫描（R0 的 --self-test 扩展版），把"局部防复现"升级为接近"全局不伪造"。
- 长期：给门禁引入真正的语义/AST 解析（现全是文本针），降低"改名绕过"风险。

建议执行节奏：**R0（1 周速赢） → R1.1 + R2.1（诚实洞 + 拆文件，可并行） → R2.2/R2.3（收敛并行态） → R1.2–1.5（核心插件链贯通，本方案最高价值） → R3（网络闭环） → R2.4/R2.5 + R4（结构再平衡 + 安全收口） → R5 持续。** 每阶段以"一条同风格真 E2E + 门禁全绿 + 数字从构建产出"为共同退出判据。

---

## 7. 一句话总结

tauron 的**治理底座是真做扎实且已贯通的**（命令层/生命周期/授权/设置持久化/恢复/白标/主题/i18n/审计，外加一套全仓罕见、真有牙齿的"绝不伪造成功"门禁体系），这些不是 PPT。**但它作为"插件系统"的题眼没有一条默认可用的端到端执行链**：框架层是 wire-only shell（`SC-9001`），四形态里只有 Process 是真链且 Production 还 fail-closed、JS 投递不诚实、WASM 引擎造好却断在整数 ABI + 未落的 supervisor、Rust 无路；网络闭环全是 trait 接缝。最大的结构债是 **21k 行单文件 lib.rs + 一堆靠锁步测试维系的并行态**；最大的"不合理"却在元层——**测试数/版本/tag 全面矛盾且被当卖点，六份重叠方案里最新的一份带着最旧的数字**。重构的正确姿势不是拆掉诚实纪律，而是**给它配上"占位必须转正或删除"的对偶约束**，先止血数字、再拆巨石收敛并行态、然后集中把 WASM/框架层两条核心链真正接通。
